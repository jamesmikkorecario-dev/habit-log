# Testing strategy

Use the single framework supplied by the Laravel 13 Livewire starter (PHPUnit). Prefer feature tests for HTTP/Livewire behavior and unit tests for isolated scoring or domain rules when those exist.

Livewire 4.4.8's [test request broker](https://github.com/livewire/livewire/blob/v4.4.8/src/Features/SupportTesting/RequestBroker.php) lets Laravel render `ModelNotFoundException` as an HTTP response, including during component mount and action calls. Assert `assertNotFound()` for owner-scoped missing/foreign/trashed records, and `assertForbidden()` for policy or session-identity rejection. Do not expect these component calls to throw `ModelNotFoundException`, disable exception handling to restore old behavior, or treat an HTTP rejection as a successful action. Direct Action tests should still assert the exception actually thrown at that boundary.

Rejection tests must also verify persisted data is unchanged: compare database-loaded attributes before and after, check row counts for unintended inserts, and include checkpoint child records where applicable. Category, lifecycle, and tracking regressions cover foreign identifiers, private category selection, stale trash saves/confirmations, and protected entries. Tracking tests additionally replay owner snapshots under another account and reject both reads and writes across all habit visibility preferences; trashed-entry tests preserve existing notes, revisions, and checkpoint outcomes.

Phase 0 covers successful and invalid registration, successful and invalid login, logout, guest denial/redirect for the application page, and authenticated access. Database tests use only `habit_log_test`, reset safely, and remain repeatable.

Phase 1 covers profile loading/saving, username uniqueness and boundaries, nullable text, literal/padded zero text, privacy defaults/toggling, theme validation, escaped identity output, and dashboard navigation. Ownership tests verify that another user's record remains unchanged and that a real Livewire update request is rejected after logout. Invalid submissions must leave all stored profile values unchanged.

CI runs on pull requests and pushes to `main` or `master`. It starts the repository's MySQL Compose service with a health wait before application setup; the initialization script creates `habit_log_test` alongside `habit_log`. Composer runs migrations for setup, then the test command runs Pint and PHPUnit. Setup also builds frontend assets.

Browser smoke testing is a separate acceptance check: register/login/logout, save and reload profile fields (including `"0"`), trigger validation, toggle privacy, and use desktop/mobile navigation with keyboard focus. A regular installed browser is sufficient; browser automation is not an application dependency. Record the browser, viewport, outcomes, and any limitations in the phase closeout report. PHPUnit request tests do not prove client-side interaction or CSRF behavior because the framework bypasses CSRF checks during tests.

Each later feature tests happy paths, validation, server-side authorization/privacy, lifecycle and date boundaries, destructive behavior, and regressions. Run focused tests while developing, then the full suite, Pint, and production asset build before handoff.

Phase 2 tests live under `tests/Feature/Categories`, `tests/Feature/Habits`, and `tests/Unit/CategoryRecommenderTest.php`. They cover recommendation ranking/normalization, seed idempotency, custom categories, all habit configurations, optional/zero goals, date and checkpoint boundaries, atomic failed writes, ownership, session expiry, lifecycle recovery, pagination, and database constraints. A dedicated migration test first checks both configured and connected database names are `habit_log_test`, then applies the explicitly selected Phase 0–2 migration set, verifies four-step rollback preserving a profile, and reapplies migrations. This remains independent of later migrations. Run these tests serially; do not run browser fixtures concurrently with database-resetting tests.

Browser acceptance separately checks Livewire form rendering, category selection/creation, all habit types, checkpoint reorder/removal, validation, lifecycle confirmations/recovery, keyboard focus, reduced motion, and mobile overflow. Existing Chrome and an available automation runtime may be used without adding a project browser dependency. Record observed results in the Phase 2 closeout report after verification.

Phase 3 tests under `tests/Feature/Tracking` cover all types, numeric/text boundaries, private notes and N/A, dated setup, checkpoint snapshots, lifecycle gaps, timezone/DST boundaries, stale revisions, authentication/ownership, pagination, schema constraints, populated upgrade, interrupted/repeated backfill, and rollback/reapply. Fixtures use real transactional Actions rather than bypassing version invariants with raw entry factories.

Concurrency verification uses independent MySQL connections with a short lock timeout and a controlled PHP subprocess that waits behind the habit lock, then checks the committed revision. It guards configured and connected database names and never uses development data. Run these tests serially; do not use parallel testing or run database-resetting suites while browser fixtures are active. Every phase closeout records actual counts and verification limits.

Browser acceptance includes saved/reloaded activity for all five types, N/A transitions, timezone settings, historical labels and backfill, pending setup, conflict feedback, dirty-form navigation, mobile layout/keyboard behavior, and normal session/request-forgery middleware. Existing browser tooling is sufficient; no browser dependency installation is required.

Phase 4 adds `tests/Unit/Analytics` for formulas, monotonicity, exact success thresholds, and segmented streak scans, plus `tests/Feature/Analytics` for historical aggregation, profile weighting, date/lifecycle/timezone boundaries, privacy, input validation, embedded Livewire interactions, locked identity, and post-logout requests. Tests verify that reads leave raw entries unchanged and that >20 habits and ancient unlogged ranges are included without per-cell queries.

A guarded, destructive test on `habit_log_test` verifies a concurrent committed checkpoint edit between parent and child reads using a second connection; the first report retains a consistent old snapshot and the next sees the new value. Run it serially with the full suite, before browser fixtures. Browser acceptance separately checks scores for every type, profile means, keyboard/date details/focus restoration, year/leap-day/list navigation, responsive scroll, private field exclusion, and normal authentication/CSRF. Record real query plans and timings from representative larger fixtures; these are scoped measurements, not production load guarantees.

The pre-commit precision regression verifies that a tiny positive profile score receives a positive heatmap band while a true-zero date remains in the zero band. Exact positive/full-success counters distinguish boundary values from floating-point residue without an arbitrary positive-score cutoff.

Phase 6 tests under `tests/Feature/Social` compare shared policy, SQL query, and route outcomes across owner/accepted/pending/nonfollower, account privacy, habit visibility, and lifecycle. They prove owner management remains denied to followers, private profile/payload projections, filtered aggregates, independent list pagination, current effective setup, session switching, and nested-component revocation. State tests cover request/approve/reject/cancel/unfollow/remove, duplicate follows, retained pending/accepted states across privacy changes, and stale replacement identities.

Guarded independent-connection tests exercise ordered user locks, simultaneous follows, opposite directions, privacy changes, cancellation/recreation and removal races, plus consistent shared analytics snapshots and next-request revocation. Populated migration tests preserve all earlier data. A mixed-visibility report spanning history batches records query count, timings, and EXPLAIN output without production-load claims. Run the full suite serially, then installed-browser multi-account acceptance for controls, dialogs/focus, permission changes, shared heatmap interaction, mobile layout, CSRF, and existing journal draft protection.

Phase 5 tests in `tests/Feature/Journals` cover journal CRUD/confirmation, required text and optional mood, Unicode/zero/newline limits, privacy/escaping, locked Livewire identity, expired/switched sessions, date/timezone/DST boundaries, stale drafts, unchanged habit analytics, database constraints, populated upgrade, and rollback/reapply. `tests/Fixtures/journal-write-worker.php` provides independent-connection races for competing creation/edit/deletion/recreation/timezone changes. The owner-lock timeout test verifies serialization even before a journal exists. A controlled SQL failure checks safe error handling without exposing private bindings.

Run the suite serially on guarded `habit_log_test` before browser fixtures. Installed-browser acceptance covers real save/reload, date controls, stale tabs, draft navigation protection, deletion dialog/focus, keyboard/mobile layouts, and normal CSRF handling. Record actual evidence and limitations in the Phase 5 closeout; no browser package is an application dependency.

## Phase 7 repeatable hardening checks

`tests/bootstrap.php` holds a shared process lock for PHPUnit; `Tests\TestCase::createApplication` verifies uncached testing configuration and configured/connected `habit_log_test` before RefreshDatabase runs. Browser/performance/restore commands use the same lock. Independent PHP workers within a test retain their existing connection guards and deliberately run under their parent's lock.

The repository now owns development-only Playwright/axe tooling and `tests/Browser` acceptance specs. `npm run test:e2e` requires explicit reset opt-in, creates isolated runtime/cache state, guards fixture setup, serves built assets with normal middleware, runs one worker without retries, and cleans up its preview. Installed Chrome works locally; CI explicitly provisions Chromium. Observed render completion and retried conditions replace arbitrary sleeps. Captured mail/reset tokens remain local and are excluded from CI uploads; synthetic failure screenshots have seven-day retention.

Main application browser specs import `test` and `expect` from `tests/Browser/fixtures.js`. Its automatic fixture resets only the runner's disposable file cache before each scenario so independent registrations from the shared loopback IP do not exhaust one another's budget. All requests and browser contexts inside a scenario still share real rate limits; never reset the cache in `register()` or between contexts. The runner passes the platform-correct cache path; opt-in and canonical-path guards prevent clearing development storage. The explicit `test:e2e` command runs the filesystem guard regression before browser setup; it does not rely on npm lifecycle hooks, which this repository disables. Keep one worker and the existing process lock. Registration failures report HTTP status, redirect path, and retry timing without credentials or response bodies. `registration-isolation.spec.js` covers real 429 responses across contexts and recovery at the next scenario boundary. See [the PR #8 fix report](PR_8_CI_FIX_REPORT.md) for reproduction evidence.

Auth regressions verify account-switch snapshots/drafts, private error reporting, headers, registration/reset limits, reset expiry/reuse, and login/logout session rotation. Existing policy, history, precision, race and snapshot tests remain required. `tests/Performance` is an explicitly invoked measurement suite, outside default CI: it records sparse/dense multi-year fixtures, queries/plans, local timings, memory and HTTP/Livewire payload sizes. Internal PHP request measurements are not network or production-load results. The guarded restore drill verifies encrypted export/import, all-table integrity and restored application behavior.

Automated axe scans, keyboard checks, touch emulation, 320–1440px reflow and 200% text checks are distinct from manual assistive-device or real Safari/Firefox testing. Record available environments and release gaps honestly. A configured CI workflow does not establish a hosted run; publication still requires authorization. Commands and setup are in [project commands](PROJECT_COMMANDS.md), and deployment-specific checks are in [the runbook](DEPLOYMENT.md).

Container development runs the same PHP suite with `docker compose exec app composer ci:check`. Host/port defaults can be overridden for the Compose network; the forced test database and actual-connection guards remain. Container and host tests share the bind-mounted process lock. Image/runtime smoke evidence is recorded in [the Docker guide](DOCKER.md#verification-record).

Account management Phase 1 adds `PasswordChangeTest`, `PasswordChangeConcurrencyTest`, and `password-write-worker.php`. Coverage includes validation/production-policy rules, hashing, per-user throttling, owner isolation, no secret flashing, transaction rollback, current-session rotation, legacy-session cleanup, revoked Livewire requests, reset-token invalidation, and byte-for-byte domain-history preservation. Independent MySQL workers prove admitted password changes and resets cannot overwrite a competing committed change. `password-change.spec.js` uses real independent browser cookies to check current-session survival, old-session/remember-cookie rejection, old/new login behavior, normal CSRF, validation focus, mobile keyboard submission, pending state, and selected axe/overflow checks. Screenshots and logs stay in ignored `storage/app/account-password-checks/`. Run all database-mutating checks serially.
